# 只读管理员

`0.2.15` 分支移植了 `feat/read-only-admin` 的 `readonly_admin` 角色，`0.2.16` 分支在同步官方 v0.2.16 时继续保留此功能，以及菜单显示设置、Redis Cluster 兼容和管理员使用声明。

## 使用

完整管理员在「用户管理」创建或编辑用户时，可选择「只读管理员」。该账号可登录管理后台，查看仪表盘、用户、分组、上游账号、调用记录、系统设置及支付统计，后台显示只读身份提示。

与完整管理员一样，首次进入后台仍需由本人确认管理员使用声明。只读账号可提交自己的声明确认，也可使用个人资料、密码、自己的 API Key、登出等自助功能。

## 权限

后端认证允许 `admin` 和 `readonly_admin` 访问后台，`ReadOnlyAdminGuard` 在主管理路由和支付管理路由统一执行只读策略：

- 管理查询与统计接口允许读取；少量使用 POST 的纯查询接口采用明确白名单。
- 管理面的创建、修改、删除、导入、账号刷新、OAuth 操作、测试、退款、恢复和重启均被拒绝。
- 上游账号和代理凭据导出、兑换码导出、管理员 API Key、其他用户或分组的 API Key 明文、备份下载链接被拒绝。
- 即使采用 GET，可能触发上游 OAuth 凭据刷新的账号模型查询、Claude 重置额度实时查询也被拒绝；本地定价目录查询仍可用。

被拒绝的请求返回 HTTP `403`，错误码 `READ_ONLY_ADMIN`。前端提示和菜单隐藏不作为权限边界，直接调用接口也受限制。某些页面仍显示管理操作入口，点击后由后端拒绝；这些入口不会授予写权限。

## 角色管理与兼容

只有完整管理员可以变更用户角色。创建或提升为 `admin` / `readonly_admin` 沿用现有 step-up 二次验证策略；若该功能开关已开启，则要求最近完成二次验证。不能将当前操作管理员自身降级，也不能将最后一个完整管理员降级为只读管理员或普通用户。

`IsAdmin()` 保留完整管理员语义，`CanAccessAdmin()` / `IsAdminRole()` 表示可进入管理后台。后台模式下只读管理员可以正常登录、使用 passkey 并续期会话。普通用户仍无法访问管理后台。

角色使用原 `users.role` 字段，无需数据库结构迁移。现有 `admin` 和 `user` 账号角色保持原值；是否创建只读账号由完整管理员决定。

## 验证

相关测试覆盖角色创建/提升、最后一个完整管理员保护、真实 JWT 认证、后台模式权限，以及主管理和支付路由中所有非查询请求的拦截。前端测试覆盖只读身份和编辑角色选项，并回归菜单显示与管理员使用声明流程。

另外使用独立 PostgreSQL / Redis 和编译后的应用验证真实登录、本人声明确认、后台查询、越权写入拒绝及数据不变、普通用户访问拒绝、完整管理员修改，以及后台模式下的只读登录与会话续期。验证不连接生产数据库，也不调用真实上游模型。
